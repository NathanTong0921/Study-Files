Poker Best-Hand Analyzer — Debug & Build

Due: July 3, 2026 · Points: 100 · Budget: ~2–3 hours · AI assistant: required

A small advanced-Python assignment. You are given a partly-working poker hand evaluator: two modules are written but contain bugs, and three more are stubs you implement. You debug, build, and test it — using an AI coding assistant the whole way. The full problem statement is in README.md inside the zip; this page is just logistics.

1. Get the code

  1. Download poker-assignment.zip from this Canvas assignment.
  2. Unzip it — you'll get a poker/ folder.
  3. Open poker/README.md: the complete spec (the five levels, the rules, worked examples, and what each file is).

2. Set up your environment

You need Python 3.11+. We recommend uv:

cd poker
uv sync                       # create the env + install pytest/ruff/mypy
uv run python -m unittest     # run the tests (or: uv run pytest)
uv run ruff check .           # lint
uv run mypy --strict level1.py level2.py level3.py level4.py level5.py

No uv? Use a virtualenv instead:

cd poker
python3 -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install pytest ruff mypy
python -m unittest

A fresh uv run pytest runs the one included example test and it should pass — that confirms your setup. Everything else is your work.

3. Use your AI assistant (and save the conversation)

This is a course about working effectively with AI coding tools, so using one (GitHub Copilot, Claude, etc.) is expected. Save your conversation to chat.md — it is part of what you submit, and your BUGS.md / REFLECTIONS.md should reflect your own understanding, not just pasted output.

4. What to submit

Re-zip your poker/ folder and upload the .zip to this Canvas assignment. Make sure it contains:

  • level1.py … level5.py — your fixed/implemented code
  • test_poker.py — your own tests (graded — no test file is provided)
  • BUGS.md — one entry per bug you fixed (where, symptom, root cause, fix, why)
  • REFLECTIONS.md — what was hard, how you found the bugs
  • chat.md — your AI conversation transcript

Do not edit hand_rank.py, poker_common.py, or poker_analysis.py — they are frozen; the grader uses its own copies and ignores (and flags) changes.

5. How it's graded

Grading is automatic, against hidden, comprehensive test sets that are deliberately broader than the worked examples — passing the examples is not enough. You're scored on: correctness of all five levels, the quality of the tests you write, your BUGS.md, and a small optional speed bonus. The detailed point breakdown is released after the deadline.

Academic integrity

Using an AI assistant is allowed and encouraged. Submitting work you don't understand is not: the bug explanations, the tests, and the reflections must be your own. chat.md must be a genuine record of your process.
